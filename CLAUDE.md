# Untis+

## Releases

Every release gets a real changelog, written before the tag is pushed:

1. Add a `## X.Y.Z (date)` section at the top of `CHANGELOG.md`. Say what the user sees change, grouped as Added, Changed, Fixed. Mention issue numbers (`#3`) where there are any.
2. The release workflow publishes that section as the GitHub release notes, so the heading must match the tag (`v0.3.2` needs `## 0.3.2`).
3. Never tag a version that has no section.
